# Revision 17 — recoverable 3D firearm selection

The optional ten-firearm preview now continues to recognize equipped weapons
after an original pickup mesh fails to load. Previously, one failed lookup
stopped the entire arsenal until the Lua module was re-enabled.

## Lifecycle and lookup changes

- A failed original mesh stays latched **per firearm**. Switching to another
  supported firearm can still attach its own 3D model. Returning to the failed
  firearm restores the original sprite; it does not retry that asset.
- While a failed firearm is selected, the Lua module checks the equipped weapon
  at most once every 0.5 seconds. These are bounded native object queries;
  the failed mesh lookup and `AssetRegistry.GetAsset` are not repeated.
- Selecting `off` and then `preview`, or reloading the Lua module, clears the
  failure latches and explicitly permits another attempt.
- The active weapon is tracked by its catalog profile, UObject address and
  full name. Replacing a weapon with a different instance of the same class
  cleans up the old owned component and muzzle lease before attaching the new
  component. The game's original weapon sprite is restored as part of cleanup.
- Class-to-profile resolution is cached using weak UObject keys, including
  unsupported classes. The cache does not intentionally retain Unreal class
  wrappers across maps.

This revision changes optional Lua selection and recovery only. Native
projectile direction, flash positioning, recoil, vibration, and the compiled
muzzle and chainsword bridges are unchanged. The diagnostic scope of
[revision 16](2026-10-10-revision16.md) still applies.

## Verification and outstanding headset check

The Lua/UEVR simulator covers the ten original firearms, same-class weapon
replacement, muzzle lease turnover, class-resolution reuse, independent
failure isolation, permanent failure latches, and bounded recovery probes.
Offline verification includes 146 Python/Lua cases and three chainsword
converter cases. Both native modules compile using MSVC x64 `/W4 /WX`, and
all four C++ harnesses pass. Package source hashes are checked separately.

`verifiedInGame=false` and `runtimeVerified=false` remain in effect. The
maintainer still needs to test an actual failed firearm, a switch to a working
firearm, and a switch back in the headset, as well as the pre-existing
projectile and muzzle-flash alignment concerns. No live profile deployment,
injection, game launch or publication is part of this revision.
