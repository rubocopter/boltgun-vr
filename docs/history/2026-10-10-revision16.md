# Revision 16 — distinguish Niagara flash fallback reasons

Firearm effects remain incorrect in the maintainer's last headset report.
This revision extends the existing passive diagnostics so the next run can
identify which Niagara path needs correction. It does not change weapon
landmarks, effect transforms, projectile origins, recoil or haptic intensity.

## Diagnostic fields

The existing five log lines still appear every six seconds, for at most eight
windows per new owned firearm lease. The Niagara line retains its original
fields and now includes:

| Field | Meaning |
| --- | --- |
| `profile` | Weapon catalog index, from 0 to 9 in `weapon_profiles.hpp` |
| `locationHook`, `attachedHook` | Whether each reflected spawn hook was registered successfully |
| `invalidComponent` | Returned component is absent, expired or not a Niagara component |
| `invalidAsset` | Asset reflection is unavailable, or the asset is absent, expired or not a Niagara system |
| `notAllowed` | System name is outside the current weapon's exact allowlist |
| `parentUnknown` | An allowed location-spawn effect has no resolvable `AttachParent` property |
| `parentPresent` | An allowed location-spawn effect already has a parent and remains untouched |
| `poseUnavailable` | Owned firing anchor cannot be read, including destroyed objects or a changed equipped weapon |
| `transformRejected` | Anchor or effect transform fails validation, including the 500 cm distance guard |

`attachedHeld` continues to combine allowed attached-spawn effects and allowed
location-spawn effects with a parent. `parentPresent` identifies the latter.
`exact` counts allowed assets before attachment/pose checks; `moved` means the
world-transform setter returned, not that the flash looked correct in VR.

Reason counts start only after the enabled, engine-thread, fresh-lease,
VR/controllers, closed-menu and warmup guards accept the callback. Raw
`atLocation` and `attached` count all intercepted calls, including unrelated
systems and rejected sessions. These fields therefore need not sum to the
raw callback totals and cannot prove ownership of an individual effect.
No object pointers, asset dumps or recordings are logged or packaged.

## Preventing mixed-weapon reports

All Niagara callback, match, move, attachment and reason counters are cleared
when a new lease is accepted. Previously the callback counters could carry
events from an earlier weapon or an inactive interval into the next report.
Hook registration and fault flags remain session state; switching weapons
must not clear a fault or re-register an existing hook.

## Headset follow-up

Fire a few shots with the Bolter and one affected firearm, waiting at least
six seconds for each diagnostic window. Note the weapon and visible symptom.
Both raw counts at zero with a hook flag at zero indicate missing hook
registration; zero counts with both hooks registered indicate no observed
calls through these paths in that window. Nonzero `attachedHeld`,
`parentUnknown`, `poseUnavailable` or `transformRejected` explain why an
allowed flash stays at its original location. Nonzero `notAllowed` can be
unrelated effects and does not justify widening the allowlist by itself.

The offline bridge harness exercises component/asset rejection, unrelated
systems, both attachment routes, missing parent reflection, unequipped
anchors, implausible transforms, per-window draining and new-lease resets.
All ten weapon profiles retain existing projectile/flash geometry coverage.
`verifiedInGame=false` and `runtimeVerified=false` remain in force. The build
is available in the repository for a separately authorized headset test;
repository maintenance does not deploy it to the live profile.

## Offline validation

MSVC x64 `/W4 /WX` builds passed all four C++ harnesses. The maintained suite
passed 142 Python/Lua cases and three converter cases. Package source hashes
match the rebuilt DLL. The isolated deployment test passed installation,
calibration preservation, unknown-file refusal, deactivation and restoration.
No live profile was modified and no game or VR runtime was started.
