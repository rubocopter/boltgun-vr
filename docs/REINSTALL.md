# Reinstalling Windows and recovering Boltgun VR

The Git repository contains the mod source, UEVR profile templates, installer,
native plugin sources, assets with attribution, tests and hash contracts. It can
rebuild the **project** after Windows is reinstalled. Git does **not** capture
the exact active profile automatically: controller bindings, personal calibration
and runtime settings under Windows user directories can differ from templates.

## Before formatting Windows

Keep the entire repository on the drive you will retain, including its **ignored**
`backups/` and `build/` directories. With Boltgun closed, run from the repo root:

```powershell
.\tools\Backup-Reinstall.ps1
```

The command creates `backups/reinstall/<timestamp>/` with a `manifest.json` and
SHA-256 hashes verified against the original files. It captures these areas:

| Snapshot directory | Windows source | Why keep it |
| --- | --- | --- |
| `uevr-profile` | `%APPDATA%\UnrealVRMod\Boltgun-Win64-Shipping` | Active UEVR settings, controller mappings, custom arsenal/chainsword calibration, scripts and plugin revisions. |
| `game-config` | `%LOCALAPPDATA%\Boltgun\Saved\Config\WindowsNoEditor` | Engine, input and game settings (INI files). |
| `steam-bindings` | `<Steam>\config\openxr` | Boltgun-specific OpenXR controller bindings, including PS VR2 mapping files. |
| `launcher-settings` | `%LOCALAPPDATA%\BoltgunVR` | Optional local path to the official UEVR injector. |

The backup excludes dumps, log files, transient pause state, recordings and
bindings belonging to other games. It **never** uploads anything. `backups/`
is Git-ignored, so even a private GitHub repository cannot restore it; retain
this folder on the separate disk or another offline backup. Before reformatting,
check that the snapshot folder and its manifest exist on the retained drive.

## After reinstalling Windows

1. Install Steam, Boltgun, the PS VR2 PC software/drivers, SteamVR/OpenXR and
   your official UEVR build. Windows user paths and the Steam installation
   folder may have changed. The native bridge also depends on a **supported
   Boltgun executable hash**; game updates can invalidate this dependency.
2. Install the game at least once and configure SteamVR with the headset.
   Exit Boltgun, SteamVR and the UEVR injector before copying your snapshot.
3. Read `manifest.json` and restore each snapshot directory to its current
   Windows destination, using the table above. Create the destination folders
   as necessary; confirm the restored file SHA-256 values against the manifest.
   If you already changed a newly generated file, save it separately first.
   Restore only **Boltgun-specific** Steam binding files into the current
   Steam `config\openxr` folder.
4. If launcher settings were restored, update the injector path from
   **Install or update the VR profile** in `Boltgun VR.cmd` if the preflight accepts your installed files.
   Otherwise preserve your customization separately, then select your official
   `UEVRInjector.exe` on a new guided setup.
5. Run `scripts/Bolter3D.ps1 -Mode status`, `scripts/Chainsword3D.ps1 -Mode status`
   and `scripts/Comprobar-perfil.ps1`. Restored custom `config.txt` and `Engine.ini` may
   produce known *byte-level* mismatch warnings; compare their content before
   overwriting them. SteamVR can also regenerate a newer binding, which
   requires checking Options/Create manually. Only VR testing confirms runtime
   behaviour.

You can verify a snapshot **without restoring** any file:

```powershell
$snapshot = 'E:\Proyectos\borugan_vr\backups\reinstall\<timestamp>'
$manifest = Get-Content (Join-Path $snapshot 'manifest.json') -Raw | ConvertFrom-Json
foreach ($entry in $manifest.files) {
    $file = Join-Path (Join-Path $snapshot $entry.area) $entry.relativePath
    if ((Get-FileHash -LiteralPath $file -Algorithm SHA256).Hash -ne $entry.sha256) {
        throw "Snapshot corrupted: $file"
    }
}
```

## If only the Git repository survives

Install Python and MSVC x64 Build Tools/Windows SDK (see [build instructions](BUILD.md)),
then run `tools/Build.ps1` to recreate native plugins and verify the hashes.
Install the original game and UEVR, then run the guided setup; it can create
the declared inputs for an empty profile. After the first UEVR injection,
repeat guided setup if SteamVR needs its controller binding patched.
Experimental 3D components can be deployed with
`scripts/Bolter3D.ps1 -Mode preview` and `scripts/Chainsword3D.ps1 -Mode install`.

The installers accept only recognised existing files and may reject files
generated by different game/UEVR versions. In that case investigate the
differences instead of forcing an overwrite. Custom calibration and SteamVR
bindings that existed only on C: **cannot be recovered from Git**.

For ordinary uninstall/restore, `scripts/Restore.ps1` reads the private
`backups/install/` snapshot produced before the first installation. This
snapshot must be preserved separately if the repository will be moved to a
fresh disk or cloned again. Re-running the installer never replaces it.

Git does not include DLL build outputs (`build/`), private snapshots, saved games,
the game, UEVR itself, or headset drivers. Preserve them separately when needed.
